**日時:** 2025-11-09 13:30
**調査者:** Claude

- **Next.js:** 15.5.5
- **ブラウザ:** 不明（ユーザー環境）

```typescript
export async function loadExpenditureData(year: Year): Promise<ExpenditureData> {
  if (expenditureCache.has(year)) {
    return expenditureCache.get(year)!;
  }

  const response = await fetch(`/data/year_${year}/project-expenditures.json`);
  if (!response.ok) {
    throw new Error(`Failed to load expenditure data for year ${year}`);
  }

  const data: ExpenditureData = await response.json();
  expenditureCache.set(year, data);
  return data;
}
```

### 3. クリックハンドラー (client/components/SankeyChart.tsx)

**実装箇所:** Line 174-209

```typescript
.on('click', async function (event, d) {
```

**問題の可能性:**
1. **エラーサイレント失敗:** console.errorは出力されるが、ユーザーには何も表示されない
2. **drilldownDataがnull:** データロードは成功したが、データ生成でnullが返される
3. **状態更新失敗:** setCurrentData()が呼ばれてもUIが再描画されない

## 推定される原因

### 仮説1: フェッチパスの問題

`/data/year_2024/project-expenditures.json` は正しく、Next.jsの`public/`フォルダは`/`としてマッピングされるため、パスは正しい。

**確認方法:** ブラウザの開発者ツールでNetworkタブを確認

### 仮説2: データ型の不一致

`expenditureData[projectId]` でアクセスする際、projectIdが数値だがJSONキーが文字列のため、アクセスに失敗している可能性。

**確認箇所:**
```typescript
// client/lib/sankeyDrilldown.ts:108
const projectExpData = expenditureData[projectId];
if (!projectExpData) return;  // ここでreturnされている可能性
```

JavaScriptでは `obj[2826]` と `obj["2826"]` は同じだが、TypeScriptの型定義によっては問題が起きる可能性あり。

### 仮説3: React状態更新の問題

`setCurrentData()` が呼ばれても、`useEffect`の依存配列が正しく設定されていないため、再描画が発生しない。

**確認箇所:**
```typescript
// client/components/SankeyChart.tsx:257
}, [filteredData, year, isDarkMode, router, config, isLoaded, data, currentData, drilldownStack]);
```

`currentData` が依存配列に含まれているため、更新は検知されるはず。

### 仮説4: 非同期処理のタイミング問題

D3のイベントハンドラー内で非同期処理を行っているため、状態更新がイベントループの外で発生し、Reactが検知できない可能性。

## 次のステップ（推奨）

### 1. デバッグログの追加

以下の箇所にconsole.logを追加:

```typescript
  console.log('[Drilldown] Ministry clicked:', params.clickedNode.name);

  console.log('[Drilldown] Loaded expenditure data:', Object.keys(expenditureData).length, 'projects');

  topProjects.forEach((project) => {
```

### 2. 型安全性の確保

expenditureLoaderの型定義を確認:

```typescript
export interface ExpenditureData {
  [projectId: string]: {  // キーは文字列
    projectId: number;
    projectName: string;
    // ...
  };
}
```

アクセス時は明示的に文字列に変換:

```typescript
const projectExpData = expenditureData[String(projectId)];
```

### 3. エラー表示UIの追加

ユーザーにエラーを表示:


### 4. ブラウザ開発者ツールでの確認

- **Console:** エラーログの確認
- **Network:** `/data/year_2024/project-expenditures.json` のリクエスト状態
- **React DevTools:** 状態の変化を確認

## 結論

最も可能性が高い原因は**仮説2: データ型の不一致**です。

JavaScriptのオブジェクトキーは自動的に文字列に変換されるため、`expenditureData[2826]` は `expenditureData["2826"]` と同じですが、明示的に文字列変換することで型安全性を確保すべきです。

## 推奨される修正

1. `client/lib/sankeyDrilldown.ts` の全ての `expenditureData[projectId]` を `expenditureData[String(projectId)]` に変更
2. デバッグログを一時的に追加してブラウザコンソールで確認
3. エラーハンドリングを改善してユーザーにフィードバックを提供
