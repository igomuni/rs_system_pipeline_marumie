# サンキー図のベストプラクティス調査

**作成日**: 2025-11-09
**目的**: DeepResearch用の調査プロンプト

## 調査背景

現在の実装では、3列構成（予算合計 → 府省庁 → 事業Top3+その他）のサンキー図を作成したが、以下の課題が発生：

1. **ノード数が多すぎる**: 府省庁数（約30）× Top3事業 = 約90ノード + その他ノード
2. **視覚的な利点の消失**: フローの太さによる予算規模の可視化効果が薄れる
3. **ツリー図化**: サンキー図というよりも単なる階層構造図になってしまう

## 調査目的

多数の項目（ノード）を持つサンキー図における効果的な可視化手法とデザインパターンを調査する。特に、データの階層構造を保ちながら、フローの太さによる視覚的な情報伝達を最大化する方法を探る。

## 現在の技術的制約

### 技術スタック
- **フロントエンド**: Next.js 15, TypeScript, React 18
- **可視化ライブラリ**: D3.js v7, d3-sankey v0.12
- **スタイリング**: Tailwind CSS
- **ビルドツール**: Webpack (Next.js内蔵)

### データ規模
- **年度数**: 11年度（2014-2024）
- **事業数**: 約4,000-10,000事業/年度
- **府省庁数**: 約30
- **総データ量**: 前処理済みJSON で約9MB（年度データ）+ 52MB（事業詳細）

### ターゲット環境
- **主要ユーザー**: 政府予算の分析を行う一般ユーザー、研究者、ジャーナリスト
- **表示環境**: デスクトップブラウザ（Chrome, Firefox, Safari, Edge）
- **画面サイズ**: 1280px以上を想定（モバイル対応は後回し）
- **パフォーマンス目標**: 初期レンダリング 2秒以内、インタラクション応答 100ms以内

### 既存の実装状況
- **データ前処理**: ビルド時にCSVからJSONへ変換済み
- **状態管理**: URLパラメータによる府省庁フィルター対応済み
- **事業詳細**: 別ページで12,573事業の検索・閲覧機能あり
