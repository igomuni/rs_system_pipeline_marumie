# marumieサンキー図実装調査

**調査日時**: 2025-11-12
**調査対象**: https://github.com/team-mirai-volunteer/marumie
**調査目的**: 5列サンキー図において4列目に要素を配置し、5列目を空にする実装方法の理解

## 概要

marumieプロジェクトは、市民によるオープンガバメント可視化プロジェクトで、兵庫県の予算・支出データをサンキー図で可視化している。本調査では、特に「(仕訳中)」ノードが表示上5列中の4列目に配置され、5列目が空になる仕組みを調査した。

## 使用ライブラリ

- **ライブラリ**: `@nivo/sankey` version 0.99.0
- **フレームワーク**: Next.js (App Router)
- **言語**: TypeScript

## 実装の核心メカニズム

### 1. 列配置の自動計算

marumieの実装では、**明示的な`column`プロパティを使用せず**、d3-sankeyの自動深度計算に依存している。

**重要な発見**: ノードの列位置は、リンクのトポロジー（接続構造）に基づいてd3-sankeyが自動的に`node.depth`を計算することで決定される。

```typescript
// リンク構造が列配置を決定
income-sub → income → total → expense → expense-sub
(depth=0)    (depth=1) (depth=2) (depth=3) (depth=4)
```

### 2. ノードタイプ定義

marumieでは5つのノードタイプを定義：

```typescript
export type NodeType =
  | 'income-sub'    // 収入サブカテゴリ（列0）
  | 'income'        // 収入カテゴリ（列1）
  | 'total'         // 総計（列2）
  | 'expense'       // 支出カテゴリ（列3）
  | 'expense-sub';  // 支出サブカテゴリ（列4）
```

### 3. "(仕訳中)"が4列目に表示される理由

"(仕訳中)"ノードは`expense`タイプ（depth=3）として定義されているため、自動的に4列目（0始まりで列3）に配置される。

5列目（`expense-sub`, depth=4）は、支出のサブカテゴリが存在する場合のみ使用される。サブカテゴリがない場合は空のままとなる。

### データ変換ロジック（`sankey-category-converter.ts`）

```typescript
function convertSankeyCategoriesToNivoFormat(categories: SankeyCategory[]): NivoSankeyData {
  const nodes: NivoSankeyNode[] = [];
  const links: NivoSankeyLink[] = [];

  categories.forEach((category) => {
    // 収入サブカテゴリノード (depth=0)
    category.incomes.forEach((income) => {
      if (income.subCategories && income.subCategories.length > 0) {
        income.subCategories.forEach((sub) => {
          nodes.push({
            id: `income-sub-${sub.name}`,
            nodeColor: income.color,
            nodeType: 'income-sub',
          });
          // income-sub → income へのリンク
          links.push({
            source: `income-sub-${sub.name}`,
            target: `income-${income.name}`,
            value: sub.value,
          });
        });
      }
    });

    // 収入カテゴリノード (depth=1)
    category.incomes.forEach((income) => {
      nodes.push({
        id: `income-${income.name}`,
        nodeColor: income.color,
        nodeType: 'income',
      });
      // income → total へのリンク
      links.push({
        source: `income-${income.name}`,
        target: 'total',
        value: income.value,
      });
    });

    // 総計ノード (depth=2)
    nodes.push({
      id: 'total',
      nodeColor: '#888888',
      nodeType: 'total',
    });

    // 支出カテゴリノード (depth=3)
    category.expenses.forEach((expense) => {
      nodes.push({
        id: `expense-${expense.name}`,
        nodeColor: expense.color,
        nodeType: 'expense',
      });
      // total → expense へのリンク
      links.push({
        source: 'total',
        target: `expense-${expense.name}`,
        value: expense.value,
      });
    });

    // 支出サブカテゴリノード (depth=4)
    category.expenses.forEach((expense) => {
      if (expense.subCategories && expense.subCategories.length > 0) {
        expense.subCategories.forEach((sub) => {
          nodes.push({
            id: `expense-sub-${sub.name}`,
            nodeColor: expense.color,
            nodeType: 'expense-sub',
          });
          // expense → expense-sub へのリンク
          links.push({
            source: `expense-${expense.name}`,
            target: `expense-sub-${sub.name}`,
            value: sub.value,
          });
        });
      }
    });
  });

  return { nodes, links };
}
```

### ノードソートロジック

```typescript
// カスタムソート: nodeTypeの順序を強制
const nodeTypeOrder: Record<NodeType, number> = {
  'income-sub': 0,
  'income': 1,
  'total': 2,
  'expense': 3,
  'expense-sub': 4,
};

nodes.sort((a, b) => {
  const orderA = nodeTypeOrder[a.nodeType] ?? 999;
  const orderB = nodeTypeOrder[b.nodeType] ?? 999;
  return orderA - orderB;
});
```

## 当プロジェクトとの比較

### marumieのアプローチ
- ✅ d3-sankeyの自動深度計算に依存
- ✅ 明示的な`column`プロパティなし
- ✅ リンクトポロジーが列配置を決定
- ✅ `align="center"`を使用

### 当プロジェクト（現在の実装）
- ⚠️ 明示的な`column: 0/1/2/3`プロパティを設定
- ⚠️ D3.jsがこのプロパティを正しく尊重していない可能性
- ⚠️ "ソースは正しそうに見えますがうまくいっていないですね"（ユーザーコメント）

## 推奨される改善策

### オプション A: marumieのトポロジーベースアプローチを採用

1. **明示的な`column`プロパティを削除**
2. **リンク構造のみで列配置を制御**
3. **d3-sankeyの自動深度計算に任せる**

メリット:
- d3-sankeyの標準動作に従う
- より安定した配置
- marumieで実証済み

デメリット:
- データ生成ロジックの大幅な変更が必要
- リンク構造を慎重に設計する必要がある

### オプション B: 現在の明示的columnアプローチを維持

1. **D3.jsでcolumnプロパティを明示的に使用**
2. **Nivoでの表示に集中**

メリット:
- データ構造は既に完成している
- 列配置の制御が直感的

デメリット:
- D3.jsとの統合に問題がある
- 標準的なd3-sankeyの使い方ではない

### オプション C: Nivoを主実装にする

1. **Nivo実装を主軸とする**
2. **D3.js実装は実験的機能として残す**

メリット:
- Nivoは既に動作している
- marumieと同じライブラリ
- 明示的なcolumnプロパティと親和性が高い可能性

デメリット:
- 既存のD3.js実装の投資が無駄になる
- Nivoの柔軟性がD3.jsより低い可能性

## 技術的洞察

### d3-sankeyの自動深度計算アルゴリズム

```
depth = ソースノードからの最大距離

例:
A → B → C → D → E
A: depth=0 (ソースノード)
B: depth=1 (Aから1ステップ)
C: depth=2 (Aから2ステップ)
D: depth=3 (Aから3ステップ)
E: depth=4 (Aから4ステップ)
```

この自動計算により、複雑なリンク構造でも適切な列配置が保証される。

## 結論

marumieの実装調査から、**リンクトポロジーに基づく自動深度計算**がサンキー図の列配置において最も安定したアプローチであることが判明した。

当プロジェクトの現在の問題（"ソースは正しそうに見えますがうまくいっていない"）は、明示的な`column`プロパティがd3-sankeyの標準動作と競合している可能性が高い。

**推奨**: Nivo実装を主軸とし、marumieのアプローチを参考に、リンクトポロジーベースの列配置を検討する。
